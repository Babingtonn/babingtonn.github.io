# AGENTS.md — Регламент розробки BLACKLINE BARBER

## 1. Суть проєкту та технології
- **Проєкт:** Демонстраційний адаптивний односторінковий сайт польського барбершопу для портфоліо. Мова сайту — польська (`pl-PL`).
- **Стек:** Семантичний HTML5, чистий CSS3 (mobile-first), ванільний JavaScript (тільки базовий UI: меню, кнопки дій).
- **Обмеження:** Жодних React, Next.js, Supabase, бекенду, баз даних, важких бібліотек чи обов'язкових збирачів. Локальний перегляд без збірки.

## 2. Головні обмеження та заборони
- **Фейкові дані:** Заборонено вигадувати справжню адресу, номер телефону, email, розміщувати фейкову Google Maps, штучні відгуки чи рейтинги.
- **Booksy та соцмережі:** Заборонено підставляти чужі чи вигадані URL. Демо-кнопка чесно повідомляє про статус демонстрації; заборонено неробочі `href="#"`.
- **Безпека й автономність:** Заборонено деплоїти сайт, купувати домени, додавати аналітичні трекери чи видаляти файли користувача без окремого дозволу.

## 3. Розподіл ролей
- **Gemini Flash (Antigravity):** Головний виконавець — тексти польською, дизайн, HTML, CSS, простий JS, адаптивність, первинний QA, точкові виправлення.
- **Codex:** Інженерний резерв — залучається виключно для складних технічних проблем (якщо Gemini не вирішив за 2 спроби) та фінального технічного аудиту на Етапі 9. Не витрачається на рутину, тексти й кольори.
- **ChatGPT:** Планування, формулювання точкових завдань на кожен етап, рев'ю звітів.
- **Користувач:** Власник проєкту — затверджує дизайн, тестує на смартфоні, схвалює перехід між етапами.
- **Правило одного редактора:** Лише один AI-агент редагує файли проєкту в конкретний момент часу. Паралельний запис заборонено.

## 4. Покрокова розробка та економія контексту
- **Поетапність:** Розробка ведеться суворо за 12 етапами (0–11). Заборонено виконувати кілька етапів за один запит або переходити далі без дозволу.
- **Економія контексту:** Повний `PLAN.md` читається один раз на Етапі 0. На наступних кроках читаються тільки `AGENTS.md`, `PROGRESS.md` і релевантний розділ `PLAN.md`.
- **Формат сесії:** Перед змінами — короткий план; після виконання — структурований звіт та оновлення `PROGRESS.md`. Зупинка до схвалення.

## 5. Мобільні вимоги (Mobile-First)
- Розробка починається з мобільного екрана: перевірка на 320, 360, 390, 430 px, далі планшет (768 px) і десктоп (1024, 1440 px).
- Жодного горизонтального скролу на будь-якому з екранів.
- Зручні розміри touch-елементів (орієнтир від ~44×44 px для основних дій).
- Читабельний текст без накладень та обрізань, фото без спотворень.

## 6. Стандарти якості та перевірок (QA)
- **Семантика й доступність:** Один H1, чітка ієрархія H2/H3, семантичні landmarks (`header`, `nav`, `main`, `footer`), обов'язковий `alt` польською.
- **Клавіатура й фокус:** Усі функції доступні клавіатурою, видимий `:focus-visible`, доступні стани `aria-expanded` для меню.
- **Чесність статусів:** Не заявляти «все працює» без фактичної перевірки. Чітко розділяти: *виконано*, *перевірено автоматично*, *потрібно перевірити вручну*.
